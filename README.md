# منصة المدربة أم هشام — تأسيس القدرات والتحصيلي

> «مع أم هشام، نفهم الفكرة قبل أن نحل السؤال»
>
> المدربة / أم هشام | 0531643142

منصة تعليمية عربية كاملة (RTL) لطلاب القدرات والتحصيلي: محاضرات PDF، تتبّع تقدّم،
اختبارات إلكترونية بأربعة أنواع من الأسئلة، ولوحة مدربة تولّد اختبارات أصلية من ملفات
الـ PDF عبر Claude API.

## ما الذي بُني فعلًا

| الصفحة | المسار | الوصف |
|---|---|---|
| الرئيسية | `/` | صفحة هبوط عربية، المزايا الخمس، بطاقات الملفات الأربعة، قسم طمأنة للطلاب |
| الملفات | `/courses` | بطاقات المقررات مع تصفية: القدرات / التحصيلي / المكتمل / غير المكتمل |
| تفاصيل الملف | `/courses/[id]` | عارض PDF مدمج، تنقّل بين المحاضرات الخمس، شريط تقدّم، أفضل وآخر درجة |
| الاختبارات | `/quizzes` | اختيار ملف ثم محاضرة، عرض أفضل درجة لكل اختبار |
| خوض الاختبار | `/quizzes/[id]` | سؤال واحد في الشاشة، مؤقّت، تنقّل، تسليم، نتيجة مفصّلة مع شرح كل إجابة |
| لوحة الطالب | `/dashboard` | ترحيب، تقدّم كل ملف، آخر ما شوهد، آخر وأفضل درجة، توصية بالخطوة التالية |
| لوحة المدربة | `/admin` | نظرة عامة وإحصاءات سريعة |
| إدارة الملفات | `/admin/courses` | رفع/استبدال PDF، تحرير العنوان والوصف والتصنيف وعناوين المحاضرات الخمس ونطاقات صفحاتها |
| **إنشاء اختبار ذكي** | `/admin/ai-quiz` | ★ توليد أسئلة عربية أصلية من نطاق صفحات محدد عبر Claude، مع معاينة وتحرير كامل قبل النشر |
| الاختبارات (مدربة) | `/admin/quizzes` | نشر / إخفاء / حذف، مع عدد المحاولات والمتوسط |
| اختبار يدوي | `/admin/quizzes/new` | بناء اختبار سؤالًا سؤالًا بالأنواع الأربعة |
| التحليلات | `/admin/analytics` | عدد الطلاب، متوسط الدرجة لكل ملف، نسبة الإكمال، الأسئلة الأكثر خطأً، جدول الطلاب |

**أنواع الأسئلة المدعومة:** اختيار من متعدد، مقارنة كمية (بالقالب المعتمد في قياس)،
صح أو خطأ، إجابة قصيرة.

## المتطلبات

- **Node.js 20.9 أو أحدث** — ✅ مثبّت بالفعل (الإصدار 24.19.0 LTS مع npm 11.17).
  للتحقق في أي وقت:
  ```bash
  node --version
  ```
  إن ظهرت رسالة «not recognized» بعد إعادة تشغيل الجهاز، أغلقي الطرفية
  وافتحيها من جديد ليُحمَّل متغيّر PATH المحدَّث.

- حساب [Vercel](https://vercel.com) — للنشر لاحقًا (اختياري).

## التنصيب خطوة بخطوة

```bash
cd om-hisham-academy
npm install
```

ثم انسخي ملف المتغيرات:

```bash
cp .env.example .env.local
```

على Windows PowerShell:

```bash
Copy-Item .env.example .env.local
```

> ملف `.env.local` مُنشأ بالفعل (نسخة من `.env.example` بقيم فارغة).
> املئي القيم حسب القسمين التاليين، ثم أعيدي تشغيل الخادم.

```bash
npm run dev
```

افتحي <http://localhost:3000>

**قبل ملء المفاتيح:** الموقع يعمل ويعرض شريط إعداد أعلى الصفحة يوضّح
الخطوات الناقصة، ويظهر كل شيء بحالات فارغة نظيفة بدل رسائل خطأ.
الشريط يختفي تلقائيًا فور اكتمال المفاتيح الثلاثة.

> **ملاحظة لمستخدمي OneDrive:** المشروع موجود داخل مجلد OneDrive. مزامنة مجلد
> `node_modules` قد تبطئ الجهاز أو تسبب أخطاء قفل ملفات. يُفضّل استثناء مجلد
> المشروع من مزامنة OneDrive، أو نقل المشروع إلى مسار خارج OneDrive
> مثل `C:\dev\om-hisham-academy`.

## إعداد Supabase

### ١) أنشئي المشروع

1. ادخلي <https://supabase.com/dashboard> ثم **New project**.
2. اختاري اسمًا وكلمة مرور لقاعدة البيانات، والمنطقة `Central EU` أو الأقرب.
3. انتظري دقيقتين حتى يجهز المشروع.

### ٢) شغّلي المخطط

1. من القائمة الجانبية: **SQL Editor** ▸ **New query**.
2. الصقي محتوى `supabase/schema.sql` كاملًا ▸ **Run**.
   يُنشئ هذا: الجداول السبعة، الأنواع، الدوال، المحفّزات، سياسات RLS، ومجلد التخزين.
3. أنشئي استعلامًا جديدًا، والصقي `supabase/seed.sql`.
   **قبل التشغيل**، غيّري السطر:
   ```sql
   values ('admin_email', 'CHANGE-ME@example.com')
   ```
   إلى بريدك الحقيقي، ثم **Run**.
   يُنشئ هذا: المقررات الأربعة، المحاضرات العشرين، واختبارًا تجريبيًا جاهزًا.

### ٣) انسخي المفاتيح إلى `.env.local`

من **Project Settings**:

| المتغير | مكانه في لوحة Supabase |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Data API ▸ Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | API Keys ▸ `anon` / `publishable` |
| `SUPABASE_SERVICE_ROLE_KEY` | API Keys ▸ `service_role` / `secret` ⚠️ سرّي |

مثال:

```env
NEXT_PUBLIC_SUPABASE_URL=https://abcdefghijklm.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
SUPABASE_STORAGE_BUCKET=course-files
NEXT_PUBLIC_SITE_URL=http://localhost:3000
ADMIN_EMAIL=your-email@example.com
```

### ٤) إعدادات المصادقة

**Authentication ▸ URL Configuration:**

- **Site URL:** `http://localhost:3000` (وبعد النشر: رابط Vercel)
- **Redirect URLs:** أضيفي `http://localhost:3000/auth/callback`
  وبعد النشر: `https://your-app.vercel.app/auth/callback`

**Authentication ▸ Providers ▸ Email:** إن أردتِ تجربة أسرع أثناء التطوير،
أطفئي **Confirm email** مؤقتًا حتى لا تحتاجي إلى فتح رسالة التفعيل في كل حساب تجريبي.

## إعداد Claude API

1. أنشئي مفتاحًا من <https://console.anthropic.com> ▸ **API Keys**.
2. أضيفيه إلى `.env.local`:

```env
ANTHROPIC_API_KEY=sk-ant-api03-...
ANTHROPIC_MODEL=claude-opus-5
```

المفتاح يُقرأ **داخل الخادم فقط** (`src/lib/anthropic.ts` يبدأ بـ `import "server-only"`)
ولا يُرسل إلى المتصفح إطلاقًا.

> بقية أجزاء المنصة تعمل بدون هذا المفتاح — صفحة «إنشاء اختبار ذكي» وحدها
> ستعرض رسالة خطأ واضحة إن كان غير مضبوط.

## رفع ملفات المحاضرات

ملفات الـ PDF كبيرة (حوالي ١٥٥ ميجابايت للأربعة) ولذلك **لا تُحفظ في Git**، بل في
Supabase Storage. أمامك طريقتان:

### الطريقة الأولى — سكربت الرفع الجماعي (الأسرع)

```bash
node scripts/upload-pdfs.mjs "C:/Users/enmrv/Downloads/المحاضرات المدربة ام هشام"
```

أو انسخي الملفات إلى مجلد `content-pdfs/` داخل المشروع ثم:

```bash
npm run upload:pdfs
```

السكربت يطابق كل ملف مع مقرره من أرقام المحاضرات في اسمه
(`المحاضرات من 1 الى 5.pdf` ← `lectures-1-5`)، ثم يرفعه ويحدّث عدد صفحاته تلقائيًا.

### الطريقة الثانية — من داخل الموقع

**لوحة المدربة ▸ إدارة الملفات ▸ رفع PDF** لكل ملف على حدة.

بعد الرفع، راجعي **نطاقات صفحات المحاضرات** من زر «تعديل» — هذه النطاقات
هي التي تحدد الصفحات التي تُرسل إلى Claude عند توليد الاختبارات.

## حساب المدربة

1. أنشئي حسابًا عاديًا من `/signup` بالبريد نفسه الموجود في `ADMIN_EMAIL`.
   محفّز قاعدة البيانات سيمنحه صلاحية `admin` تلقائيًا.
2. إن أنشأتِ الحساب قبل ضبط البريد، رقّيه يدويًا:

```bash
node scripts/make-admin.mjs your-email@example.com
```

3. سجّلي الدخول ثم افتحي `/admin`.

**كل الطلاب الآخرين** يُنشأون بدور `student` تلقائيًا، ولا يستطيعون رفع ملفات ولا توليد
اختبارات ولا رؤية التحليلات — سياسات RLS تمنعهم على مستوى قاعدة البيانات نفسها،
لا على مستوى الواجهة فقط.

## النشر على Vercel

```bash
git init
git add .
git commit -m "منصة المدربة أم هشام"
git branch -M main
git remote add origin https://github.com/USERNAME/om-hisham-academy.git
git push -u origin main
```

ثم:

1. <https://vercel.com/new> ▸ **Import** المستودع.
2. Vercel يكتشف Next.js تلقائيًا — لا تغيّري إعدادات البناء.
3. في **Environment Variables** أضيفي **كل** المتغيرات من `.env.local`:

   | المتغير | ملاحظة |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | |
   | `SUPABASE_SERVICE_ROLE_KEY` | ضعيه كـ **Sensitive** |
   | `SUPABASE_STORAGE_BUCKET` | `course-files` |
   | `ANTHROPIC_API_KEY` | ضعيه كـ **Sensitive** |
   | `ANTHROPIC_MODEL` | `claude-opus-5` |
   | `NEXT_PUBLIC_SITE_URL` | رابط Vercel النهائي |
   | `ADMIN_EMAIL` | بريد المدربة |

4. **Deploy**.
5. بعد نجاح النشر، عودي إلى Supabase ▸ **Authentication ▸ URL Configuration**
   وحدّثي **Site URL** و**Redirect URLs** برابط Vercel.
6. حدّثي `NEXT_PUBLIC_SITE_URL` في Vercel بالرابط النهائي ثم أعيدي النشر
   (**Deployments ▸ ⋯ ▸ Redeploy**).

> **مهلة تنفيذ التوليد:** مسار `/api/ai/generate-quiz` مضبوط على `maxDuration = 300`
> ثانية. الخطة المجانية في Vercel تحدّها عند ٦٠ ثانية، وهو ما يكفي لأغلب النطاقات
> الصغيرة (١٠–٢٠ صفحة). للنطاقات الكبيرة تحتاجين خطة Pro، أو قلّلي عدد الصفحات.

## كيف تعمل ميزة «إنشاء اختبار ذكي»

```
المدربة تختار: ملف + (كامل | محاضرة | نطاق صفحات) + عدد + صعوبة + نوع + وقت
        ↓
POST /api/ai/generate-quiz        (مسار خادمي)
        ↓
١. تحقّق من أن المستخدم admin ← غير ذلك: 403
٢. تحديد نطاق الصفحات الفعلي من جدول lectures
٣. تنزيل الـ PDF من Supabase Storage بمفتاح الخدمة
٤. pdf-lib يقصّ **الصفحات المحددة فقط** إلى ملف صغير
٥. إرسال الشريحة إلى Claude كـ document/base64 + موجّه صارم
٦. Claude يعيد JSON مطابقًا للمخطط، ويُتحقق منه بـ zod
        ↓
معاينة كاملة في الواجهة: تحرير النص والخيارات والإجابة والشرح،
حذف وإعادة ترتيب، إضافة أسئلة يدوية
        ↓
«اعتماد ونشر» أو «حفظ كمسودة»  ← الآن فقط يُكتب في قاعدة البيانات
```

**لماذا نرسل الـ PDF نفسه بدل نص مستخرج؟**
ملفات المحاضرات صور ممسوحة ضوئيًا بلا طبقة نص (فُحصت: ٤٨٠ صورة مضمّنة ولا نص
قابل للاستخراج). أي محاولة لاستخراج النص برمجيًا ستعيد صفحات فارغة. لذلك تُرسل
الصفحات المقصوصة إلى Claude ليقرأها بصريًا — وهي الطريقة الوحيدة التي تعمل مع هذا
النوع من الملفات، وتعمل أيضًا مع أي ملف نصي ترفعينه مستقبلًا.

**صيغة الإخراج المتفق عليها:**

```json
{
  "title": "عنوان الاختبار",
  "questions": [
    {
      "question": "نص السؤال",
      "question_type": "multiple_choice | quantitative_comparison | true_false | short_answer",
      "choices": ["أ) …", "ب) …", "ج) …", "د) …"],
      "correct_answer": "الإجابة الصحيحة",
      "explanation": "شرح عربي واضح",
      "difficulty": "easy | medium | hard",
      "related_topic": "اسم الدرس أو الفكرة"
    }
  ]
}
```

**قالب المقارنة الكمية** كما هو مطلوب في اختبار قياس:

```
القيمة الأولى: …
القيمة الثانية: …

أ) القيمة الأولى أكبر
ب) القيمة الثانية أكبر
ج) القيمتان متساويتان
د) المعطيات غير كافية
```

**الأصالة:** الموجّه يمنع النموذج صراحةً من نسخ أي سؤال أو جملة من الملف، ويطلب
منه استخراج المفهوم ثم بناء سؤال جديد بأرقام وسياق مختلفين. ومع ذلك تبقى مراجعتك
قبل النشر هي الضمانة الأخيرة — ولهذا لا يُحفظ شيء قبل أن تعتمديه.

**حدود عملية:**
- أقصى ٤٠ صفحة في التوليد الواحد (`MAX_PAGES_PER_GENERATION` في `src/lib/constants.ts`).
- عند اختيار «الملف كامل» تُؤخذ عيّنة من منتصف الملف، مع إشعار واضح لك بذلك.
- أقصى ٣٠ سؤالًا في الاختبار الواحد.

## الأمان

| الطبقة | ما تفعله |
|---|---|
| `src/proxy.ts` | يمنع الوصول لـ `/admin` و`/dashboard` و`/quizzes` بلا جلسة، ويحدّثها |
| `src/app/admin/layout.tsx` | تحقق ثانٍ من دور `admin` قبل عرض أي صفحة إدارية |
| كل Server Action | `requireAdmin()` داخل الإجراء نفسه — لا اعتماد على الواجهة |
| Row Level Security | مفعّلة على الجداول السبعة جميعًا |
| `quiz_questions` | **الطلاب ممنوعون من قراءته كليًا** لأنه يحوي الإجابات الصحيحة |
| `/api/quizzes/[id]/questions` | يعيد الأسئلة بعد حذف `correct_answer` و`explanation` |
| `/api/quizzes/[id]/submit` | التصحيح يتم على الخادم — الإجابات لا تصل للمتصفح قبل التسليم |
| `import "server-only"` | يجعل البناء يفشل إن تسرّب ملف يحوي مفاتيح إلى المتصفح |
| Storage | مجلد خاص (غير عام)، والملفات تُقدَّم عبر روابط موقّعة تنتهي بعد ساعة |
| ترقية الدور | سياسة `profiles_update_own` تمنع الطالب من ترقية نفسه إلى admin |

## ملاحظات مهمة عن محتوى الملفات

اقرئي هذا القسم — فيه ما يحتاج مراجعتك.

1. **عناوين المحاضرات العشرين ونطاقات صفحاتها قيم افتراضية.**
   ملفات الـ PDF صور ممسوحة ضوئيًا بلا نص قابل للقراءة برمجيًا، فلم يكن ممكنًا
   استخراج العناوين الحقيقية منها. العناوين الموجودة في `seed.sql` مبنية على
   التسلسل المعتاد لمنهج القدرات (الحساب ← الجبر ← الهندسة ← التحليل واللفظي)،
   ونطاقات الصفحات مقسّمة بالتساوي على خمس محاضرات لكل ملف.

   **صحّحيها من:** لوحة المدربة ▸ إدارة الملفات ▸ تعديل.
   هذا مهم عمليًا لأن نطاق الصفحات هو ما يحدد الصفحات المرسلة إلى Claude.

2. **التصنيف الافتراضي لكل الملفات الأربعة هو «القدرات».**
   لأن أسماء الملفات ومحتواها المتوقع يشيران إلى ذلك. إن كان أحدها للتحصيلي،
   غيّري تصنيفه بضغطة من الشاشة نفسها — وسيظهر مباشرة تحت فلتر «التحصيلي».

3. **بطاقات الملفات تعمل قبل رفع الـ PDF**، لكن عارض الملف وميزة الاختبار الذكي
   يحتاجان رفع الملفات أولًا.

## حل المشكلات الشائعة

**`node: command not found` أو `npm` غير معروف**
Node.js غير مثبّت. نزّلي نسخة LTS من <https://nodejs.org>، ثم **أغلقي الطرفية وافتحيها من جديد**.

**`المتغيران NEXT_PUBLIC_SUPABASE_URL و SUPABASE_SERVICE_ROLE_KEY مطلوبان`**
ملف `.env.local` ناقص أو لم يُعد تشغيل الخادم بعد تعديله. أوقفي `npm run dev` بـ `Ctrl+C` ثم شغّليه.

**صفحة `/admin` تعيدني إلى `/dashboard`**
الحساب ليس `admin`. شغّلي `node scripts/make-admin.mjs your-email@example.com` ثم سجّلي الخروج والدخول.

**«لا يوجد ملف PDF مرفوع لهذا المقرر»**
شغّلي `npm run upload:pdfs` أو ارفعي الملف من إدارة الملفات.

**«لم تُحدَّد صفحات هذه المحاضرة»**
افتحي إدارة الملفات ▸ تعديل، واملئي «من صفحة» و«إلى صفحة» لكل محاضرة.

**عارض الـ PDF فارغ على الجوال**
بعض متصفحات الجوال لا تعرض PDF داخل `iframe`. اضغطي «فتح في نافذة جديدة».

**التوليد يفشل بخطأ مهلة على Vercel**
قلّلي نطاق الصفحات إلى ١٠–١٥ صفحة، أو رقّي الخطة إلى Pro.

**رسالة تفعيل البريد لا تصل**
أثناء التطوير: Supabase ▸ Authentication ▸ Providers ▸ Email ▸ أطفئي **Confirm email**.
